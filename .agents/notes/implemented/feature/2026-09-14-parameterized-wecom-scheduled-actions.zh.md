# Agent Note: 参数化企业微信定时动作

Status: implemented

[English](2026-09-14-parameterized-wecom-scheduled-actions.md) | 中文

## 问题

企业微信调度器最初只允许完全静态的部署条目。Trader Ops 可以定时执行 `ps_check`，但用户要求执行另一个 bssh_ops 当前已配置的快捷命令或准确的自定义 shell 时，要么会立即执行，要么无法表示为持久化未来执行。在 Harness patch 中枚举全部远端快捷命令 key 会重复易变的 bssh_ops 配置，而把任意命令文本放入已发布的定时动作记录会改变其持久格式。

## 决策

定时动作定义可以声明一个字符串 `input`，包括准确的目标工具参数、模型可见说明、正数 UTF-8 字节上限，以及可选的锚定正则表达式。`scheduled_action_create` 会持久化准确的准入值，并在创建与列表结果中返回该值。静态动作拒绝输入；参数化动作拒绝缺失、空白、含 NUL、超长或不匹配表达式的输入。

动态值存入版本化的 `channel_wecom_scheduled_action_input` storage domain，并以定时动作 id 为 key。创建流程先写输入，再提交动作；动作提交失败时删除输入。启动时删除没有对应动作的输入记录。参数化记录缺少输入时，调度器拒绝执行；否则只把该值注入已配置的顶层参数，并在通知后删除两条记录。恢复出的 running 动作不会重放，同时删除两条记录。已发布的 `channel_wecom_scheduled_action` 记录及静态定义指纹保持不变。

Trader Ops 配置 `quick_command`，将安全 key 写入 bssh_ops `run_quick_command.command`；配置 `custom_shell`，将准确命令写入 `run_quick_command.custom_shell`。两者接受任意非空单行目标，实际目标由 bssh_ops 在派发时授权。bssh_ops Skill 会在定时 key 前获取当前快捷命令清单。对于自定义 shell，它会检查语法，展示准确目标、完整命令、预期影响和回滚方式，并在定时前要求用户明确确认。持久化输入禁止包含密钥。到点执行仍经过 Harness 工具策略，bssh_ops 继续负责自身的命令校验、授权与审计。

静态 `ps_check` 兼容动作继续保留。它已有的指纹和 pending 记录可跨本次发布继续工作。

## 安全与恢复

参数化输入提高了定时记录的权限，任意 shell 尤其如此。用户确认要求属于 Agent 工作流规则，并非加密审批令牌；需要独立强制审批的部署必须先增加持久审批能力，再暴露 `custom_shell`。当前部署依赖企业微信准入白名单、受限非交互 Agent preset、Harness 工具策略、MCP 身份验证、bssh_ops 授权与审计，以及持久化输入禁止凭据的规则。

调度器在派发前提交 running，并且绝不重复执行恢复出的 running 操作。这在进程丢失时保持至多一次派发，但可能报告结果不确定。bssh_ops 调用通常会在远端命令结束前返回 `run_id`，所以到期通知报告已接受触发；最终命令输出仍可通过 `get_run_status` 和提供方审计记录获取。

## 考虑过的替代方案

**把每个快捷命令 key 声明为静态 Harness 动作。** 拒绝，因为这会重复实时 bssh_ops 命令注册表，并要求运维每次更改该注册表时都发布 Harness。定时工作流改为获取当前 key，bssh_ops 会在派发时拒绝已经失效的 key。

**把输入存入已发布的定时动作记录。** 拒绝，因为新增字段会改变已经发布的持久记录格式并增加回滚复杂度。独立的版本化 domain 保持原 generation 可读，并使旧版本面对不认识的参数化动作 id 时拒绝执行。

**把 Schedule 提醒当作命令执行。** 拒绝，因为到期 Schedule prompt 是普通的不可信会话内容，并不拥有持久远端操作派发能力。专用调度器持久化结构化权限，并且只调用运维配置的工具。

**允许自由工具名或参数对象。** 拒绝，因为这样会让模型输入选择新能力或覆盖部署拥有的参数。配置固定工具、目标参数、目标表达式、静态参数和唯一动态参数。

## 验证

假时钟测试覆盖准确快捷命令与多行 shell 持久化、到点参数构造、UTF-8 与表达式校验、动作写入回滚、输入缺失时拒绝执行、孤儿清理、pending 重启恢复、恢复 running 清理、策略拒绝、定义漂移、取消和调度器静默完成。Trader Ops 的已记录 Session 固定参数化管理工具 schema。部署验证检查两个动态动作 id 及其目标参数。

## 结果

- 所有当前和未来 bssh_ops 快捷命令 key 都可以在不修改 Harness patch 的情况下定时执行，但仍受清单查询时与派发时的提供方校验。
- 经过必需的审阅与确认工作流后，可以定时执行用户准确给出的 shell 命令。
- 动态输入会持久保存，并显示在定时动作管理结果中，因此绝不能包含凭据或其他密钥。
- 回滚到旧版本不会误解释动态输入；参数化动作如果在旧版本运行期间到期，会作为未知定义封闭失败，并可能在失败通知后被移除。
